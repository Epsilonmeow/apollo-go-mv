# 工程结构

中文 | [English](ARCHITECTURE.en.md) · [返回项目首页](../README.md)

公开版由两部分组成：原版影片渲染代码，以及独立的播放、服务和导出工具。影片内容保持在原有段落目录中，避免把后续试验镜头混入 4:12.73 原版。

## 从时间到一帧画面

```text
播放器或导出工具提供影片秒数 t
  → finale/main.js 选择该时刻的段落
  → timing.js / 段落状态函数确定镜头和击打
  → Three.js 更新程序化模型与相机
  → Canvas 2D 绘制文字、图形和工程关系
  → 着色器合成三维场景与透明图形层
  → WebGL canvas
```

实际入口位于 `film/apollo-finale/main.js`。它复用之前各段的模块，而不是把多个完成的视频串接起来。

| 影片时间 | 主要模块目录 | 内容 |
| --- | --- | --- |
| 0–46 秒 | `apollo-go/` | 地面系统、地月距离、判断链与轨道待命 |
| 46–88 秒 | `apollo-first-go/` | 准备、第一轮 Go 点名、共同批准 |
| 88–111.8 秒 | `apollo-descent/` | 动力下降、推力与运动、地形观察和回传 |
| 111.8–144 秒 | `apollo-second-go/` | 两遍回复、当前性能与未来余量、继续着陆 |
| 144–184 秒 | `apollo-landing/` | 计算机报警、最后接近、接触和着陆 |
| 184–214.8 秒 | `apollo-stay/` | 落地后的持续运行与 Stay 判断 |
| 214.8 秒–曲终 | `apollo-finale/` | 月面、轨道和地面的重新连接 |

这些时间是影片时间，不是阿波罗任务时间。

## 三种图形职责

- **空间模块**负责模型、材质、光照、相机和场景锚点。飞船、月面与地球是程序化视觉模型，不依赖外部三维模型下载。
- **图形模块**用 Canvas 2D 画文字、线条、关系图和状态变化。部分标注根据三维对象投影的位置放置，使说明贴近它正在解释的对象。
- **总合成模块**将图形画布转为纹理，与三维渲染目标合成，加入少量击打缩放、噪声和暗角。Archivo 用于主要字形；等宽文字使用包含 Consolas 的系统字体栈。

图形层以 1920 × 1080 的构图设计；改变输出分辨率并不会自动生成新的竖屏版式。不同系统的等宽字体、字形栅格化和 WebGL 实现可能造成细微差别。

## 播放与确定时间渲染

主入口暴露 `window.demo`，包括 `ready`、`duration`、`render(t)`、`setSize(width, height)` 和 `stats()`。初始化完成前不能直接导出有效帧；工具需等待字体和场景准备好。

播放时由播放器给出当前时间，有本地音频时按音频时钟推进。导出时工具依次给出 `start + frameIndex / fps`，使帧数和镜头位置可重复，不以截图耗时作为影片时钟。

原动画主要按绝对时间计算状态，因此可以跳到指定时刻，不必先播放全部前文。这种设计用于稳定定位和检查，不承诺跨硬件逐像素相同。

## 导出与验证

导出工具启动本地服务与独立无界面浏览器，等待渲染入口就绪，按指定时间生成图像；视频模式再交给 FFmpeg 编码。音频仅来自调用者明确指定的本地文件。完整操作见 [README](../README.md#导出图片或视频)。

- `npm test`：静态文件与服务器检查。
- `npm run check`：浏览器内的播放器和渲染入口检查。
- 短片导出：验证实际浏览器、GPU、字体和 FFmpeg 组合可用，再启动完整渲染。
- 最终观看：确认声音版本、同步、字幕、画面与片尾是否符合预期。

原制作阶段的分段导出和保留画面对照属于历史验证；它们不能替代公开工程在新机器上的检查。这个仓库没有将旧检查记录冒充为新环境的完整渲染证明。
